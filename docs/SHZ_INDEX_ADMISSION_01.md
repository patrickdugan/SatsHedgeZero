# INDEX-ADMIT-01: recursive ordered admission with a binary-carry frontier

Registered 2026-11-24, stacked on INDEX-MAX-01 at `b93a599205d64c0f8de41bbac89cb80635ba4bda` (PR #12). Scope: structural history of the admitted log. No changes to Gemini's source adapters, NEAR verifier, SPV, FROST, or the existing policy/maximality relations. No mainnet authorization.

## 1. What is now proved, conditional on a successful Nova verification

Starting from the canonical sentinel-only state, the relation proves an ordered sequence of appends and seals. It preserves the exact `SHZ/LOG/*/V2` SHA-256/minimum tree and `SHZ/LOG/SNAPSHOT/V2` format of MAX-01. It admits only bounded positive prices, nonzero report digests, and timestamps strictly greater than the preceding tail and preceding seal. It prevents leaf substitution, deleted subtrees, skipped carries, capacity overflow, and watermark regression. A seal preserves the admitted history and strictly increases the watermark. Strict increase is an intentional subset of MAX-01's nondecreasing seal rule; redundant no-op seals need not be proved.

The proof authenticates the structural contents of a committed log; an admission digest by itself says nothing about the underlying source signature or provider completeness. It does not prove that any declared watermark was authorized or had passed in real time. The final snapshot is checked against the receiver's independently retained expected pin. It cannot be chosen by a prover and then accepted as authoritative by default.

## 2. Frontier invariant and exact root reconstruction

Let N be the number of leaves including the absence sentinel at index 0. For a fixed depth D, the tree has 2^D slots, of which at most 2^D-1 contain actual reports. An idle frontier contains one summary `(minimum_u64, digest32)` per occupied level i, representing a disjoint complete subtree of 2^i leaves. Occupied levels are exactly the 1 bits of N. From highest to lowest occupied level, these subtrees partition the ordered prefix from index 0 to N-1. No leaves occur in the empty suffix. Inactive slots use `(false,0,zero32)`, distinct from the protocol's canonical empty subtree with minimum `MAX_U64`.

A pending carry C at level ell is a new rightmost complete subtree with 2^ell leaves. Its mass plus the occupied frontier mass is N. All levels below ell are empty while a carry is pending. The three operations are:

* APPEND, idle only: verify record bounds, `t > tail`, `t > seal`, and capacity. Hash the exact real leaf with `present=1`, increment N and set tail=t, create a pending carry at level 0.
* CARRY, mandatory while pending: select exactly the carried level. If occupied, merge its earlier subtree on the left with C on the right using the exact MAX-01 node hash, enforce strict minimum order, clear that slot, and increment the carry level. If empty, put C into that slot and return idle. A merge at level D is forbidden.
* SEAL, idle only: preserve every frontier slot, N and tail; advance the watermark strictly below the reserved infinite timestamp. Dummy record/watermark inputs on other operations are constrained to zero.

Induction establishes the partition, ordered prefix and exact subtree minima. The base is the native, independently constructed sentinel leaf. Each append starts a new singleton to the right of the entire old prefix; mandatory carries join only adjacent equal-sized subtrees in the correct order. The only operation that writes a previously empty slot places that exact carried subtree. The seal does not alter the partition. Hence no authenticated minimum can be invented or changed independently of the actual leaves under collision resistance.

The verifier reconstructs the ordinary padded MAX-01 root from the **proved public terminal frontier**, using at most D native SHA256 node hashes. If level D is occupied, return that full-tree summary. Otherwise initialize r to the canonical empty leaf; for i=0..D-1 set r=node(frontier[i],r) when level i is occupied, else r=node(r,default[i]). This places the canonical empty suffix exactly to the right of the admitted prefix. Recompute the byte-exact MAX-01 snapshot pin from network genesis, fixed policy digest, source ID, depth, N-1, tail, seal, and r. Compare it to the independent pin. These native SHA checks are a required part of the proof verifier, not a new trusted attestation. The frontier is public, and reveals the minima and hashes of these complete subtrees; it is not a claim of full log privacy.

## 3. R1CS and public-state binding

The implemented depth-4 Pallas/Vesta Nova circuit uses 32 field elements: nine state fields (operation counter, N, tail, seal, pending flag, level, carry minimum and two digest limbs), five frontier slots with four fields each, and three immutable context fields (genesis limbs, source ID). All 256-bit digests have two injective 128-bit little-endian-by-byte limbs. All integer inequalities are constrained with bounded Boolean slack decompositions. The source ID is independently fixed at initialization and carried unchanged; it does not authenticate the source data by itself. The verifier reconstructs public parameters from a fixed blank step, not from prover-provided code or a verification key. It binds both the independently computed genesis and the complete terminal state.

One-hot operation bits sum to one. The carry opcode equals the pending bit. One-hot level selection sums to the carry bit and its weighted sum equals the level. The selected occupied bit determines merge versus placement. Mass conservation, empty-slot zero encodings, lower-slot emptiness during carry, capacity, and literal operation count are constrained. The selected slot and the actual carried summary feed the node SHA gadget. Each output state field is determined by the selected transition; untouched slots and immutable context are constrained to remain unchanged. A seal is impossible during a carry. The final receiver check requires an idle state, nonzero watermark, matching step count (1..128 in this pilot), exact reconstructed root, and correct snapshot pin.

The relation has a fixed synthesis shape across append, merge, placement, and seal. It deliberately computes both the two-block leaf hash and the two-block node hash each microstep. Opcode gates connect only the relevant hash to the next state. No witness-dependent constraint selection. R1CS tests include forged leaf values with recomputed leaf hashes, changed carry minima/digests, backfill at the seal, slot substitution, dropping a carry, sealing during carry, full-capacity overflow, and false terminal state. The proof verifier also checks an altered initial source, forged sentinel, changed terminal watermark, wrong step count and trailing proof bytes. Actual Rust and compressed-proof checks require successful CI; the reference results alone do not establish a cryptographic proof.

## 4. Cost model and scaling question

With M new reports and S seals, there are M leaf creations, M placements, and M+1-popcount(M+1) merges. The exact microstep count is `T=3M+1-popcount(M+1)+S`. The fixed-shape circuit uses four SHA-256 compression blocks per microstep, including the unused hash gadget and seal/placement steps. Reopening old and new Merkle paths at every append requires at least `M*(4D+2)` compression blocks under the existing leaf and node encodings (two blocks per node, two for the real leaf, excluding seal checks). At depth 18, M=144,000, S=1, the two counts are 1,727,984 and 10,656,000 blocks, a ratio of approximately 6.17. This is an analytical SHA workload comparison, not a measured R1CS speedup or gas estimate. The previous depth-18 benchmark was native reference hashing. The depth-18 circuit and hundreds of thousands of folds remain unimplemented; a production deployment needs substantially larger step limits, throughput measurements, and checkpoint/resume or batch folding. Even the improved construction can be too costly for a full 200-ms stream. Future work can test one selected explicitly padded SHA message per microstep, direct placement after a leaf/merge, and grouped microsteps. Preserve exact V2 hashes rather than silently changing the root protocol.

## 5. Composition acceptance

For the frozen synthetic POLICY-01 / MAX-01 fixture, both structural histories produce exactly the original source pins: Pyth `0e48d75d12191e590d5dd33c8e5a4a0922c51535ecc1bf8ee23462b1326547d9` (12 admitted reports, 36 microsteps); Chainlink `56b6ae1063f8b610b6afe9aeff37a983953ef3dcbde80b510191b12148b46a09` (7 admitted reports, 23 microsteps). Each uses an intermediate and final seal. A composite receiver verifies each admission proof and reconstructs both pins, verifies the MAX-01 proof against those pins, verifies the POLICY-01 proof against the exact shared evidence queue/root, and checks the exact final SHZIDX01 checkpoint. These remain separate proof invocations, not a recursively aggregated end-to-end proof. Only after each verification succeeds may structural history be treated as established. Do not accept a proof digest or log-builder assertion in place of any verification.

The native reference tests all depth-4 prefix lengths and checks the frozen two-source bridge. Duplicate report digest rejection across a whole log is not an independent circuit nullifier invariant; real admission must bind the digest to authenticated timestamp and source, or provide a separate nullifier proof. A provider that withholds updates, a relayer that omits them before admission, or an unauthorized early seal can still affect the log; authenticated observation availability/completeness and watermark authority are explicit unsolved gates. The transparent proof system introduces no trusted setup. NEAR full Nova verification, provider authentication, Bitcoin header finality and DLC authorization remain disabled.
