## Decompose verifier work without changing proof semantics

The genuine ADMIT-08 receipt has 4275 pair calls, 354 base-slice calls, 1 extension-slice call, 5661 hash permutations. Its approved upstream verifier uses Poseidon2 and the patched control root. The batch prover is an untrusted relayer. Each call record consists of kind:u8 (0 pair, 1 base, 2 ext), n:u32le, n reduced Montgomery u32le words, and eight reduced digest u32le words. Pair requires n=16; ext requires n divisible by four. Every batch is count:u32le followed by exact records, bounded to 512 calls, 512 sponge permutations, 64 KiB. Each call requires the exact ADMIT-09 Poseidon2 computation, using the same flattened overwrite-mode sponge for the three interfaces. The contract recomputes every output before changing state. It rejects noncanonical words, wrong lengths, false results, nonempty trailing bytes, excessive work and invalid offsets.

Commitment C0 = SHA256("SHZ/STARK/CACHE/START/V1" || receipt_sha256 || image_words_le || journal_len_u32le || expected_journal || expected_calls_u32le). For frame F at cursor i, Cnext = SHA256("SHZ/STARK/CACHE/BATCH/V1" || Cprev || i_u32le || len(F)_u32le || F). Cursor advances by the actual call count only after complete frame verification. Count and frame limits are receiver-fixed and state is bounded. The full transcript consists of length-prefixed frames, at most 1 MiB. The final transaction reconstructs the commitment and exact cursor and batch count from those supplied bytes. No need to store the entire 500+ KiB trace on chain or perform thousands of storage reads. Expected proof hash, approved image, journal and patched control root are retained independently; this is a fixture-specific self-only research session. A malicious relayer may submit irrelevant but valid computations, wasting work, but cannot obtain acceptance. Reset before verification is permitted only by the session owner. No public deployment or transferable authorization.

## Soundness

Assume SHA-256 collision resistance, correctness of exact Poseidon2 implementation and patched upstream verifier. Inductively every committed frame contains only correct hash outputs; a complete matching transcript opening recovers those same ordered frame bytes. The final verifier replaces only the hash interface: for each invocation it compares kind, length and **every actual Montgomery word** against the next authenticated entry and returns that previously verified output. It uses the original RNG and canonical digest checks. The replay adapter requires exact consumption and no mismatched input at termination. In every successful replay, each hash result equals ordinary upstream execution, including adversarial transcript-derived inputs. Induction over deterministic execution then establishes equivalence with the upstream verifier for all accepting executions. Upstream FRI, Merkle, algebraic constraints, Fiat-Shamir, control ID, claim and successful-exit checks all execute in the final transaction. A hash transcript or matching receipt digest alone conveys no verification. A false output is rejected at batch admission. A correctly computed hash of an unrelated input may pass batch admission, but final replay must reject it even when its own full commitment is valid. The verified bit is set only on complete successful final replay and is immutable afterward. A gas trap or incomplete replay never sets it.
