# ADMIT-08: patched succinct STARK verifier and NEAR feasibility gate

Parent: PR #20 at `6db183ae59d2b56694fa6abbb5db0d71cbf57ffd`. The initial native Rust and reference checks passed, but both original workflows failed during Cargo resolution because `risc0-zkvm=3.0.6` was yanked. The November 11, 2026 upstream critical advisory GHSA-g6qg-9j8p-7j87 requires 3.1.0 and regenerated receipts. It describes noncanonical BabyBear bit decompositions in the recursion program as well as an underconstrained Groth16 wrapper. This work uses only the patched succinct STARK route. Do not revive the yanked package or retain its control root. See https://github.com/risc0/risc0/security/advisories/GHSA-g6qg-9j8p-7j87 and the v3.1.0 upstream workspace manifest.

## Patched version and verification boundary
Pin zkVM 3.1.0 in host, guest and verification-only WASM; matching build crate 3.0.7, recursion/RV32IM circuit family 4.1.0, ZKP 3.0.6. Check all resolved lockfiles for the patched dependency family. Receipt verification explicitly requires a Poseidon2 succinct receipt, patched default succinct verifier parameters and a verifier context with no Groth16/composite/fake verification parameters. The independently compiled guest image and complete 251-byte journal remain receiver-owned expectations. The structural relation and exact tree commitments remain ADMIT-07. Neither report signatures nor seal authority are established. No Groth16 receipt, setup ceremony or remote prover used.

## Instrumented actual verification
After a real recursive proof is independently verified, count calls at the upstream Poseidon2 hash and Fiat-Shamir interfaces through delegating wrappers. Count hash-pair calls, base/extension-element slice lengths, digest checks, RNG constructions, mixes and random draw calls. For the hash calls only, count sponge permutations as max(1, ceil(number of absorbed base elements/16)); extension elements contribute four base elements, pairs contribute sixteen. RNG-internal permutations, SHA-256 claim hashing and circuit field operations are outside this counter. Instrumented timing includes counter and wrapper overhead; normal verifier time is separately recorded. Save actual control ID, control root, verifier-parameter fingerprint, seal words and receipt size. A real mutated seal must fail native verification even with its original journal.

## NEAR feasibility experiment
A standalone verification-only crate (no prover feature) is built to wasm32-unknown-unknown using the existing NEAR SDK pin. Its self-only initializer installs an independently produced image and exact canonical journal for the registered fixture. Verify the bounded, fixint, trailing-byte-rejecting receipt through the upstream patched Rust STARK verifier. It performs no authorization or state update. The ephemeral sandbox submits the real root receipt with 300 TGas, records receipt-level gas and status, and checks a real changed seal, truncated and trailing data. A compilation, WASM deployment, payload size or gas failure is a recorded feasibility failure. It is not grounds to bypass cryptographic verification or enable authorization. All source, provider completeness, seal, finality, production and DLC gates remain open. No claim of NEAR verification before a successful actual transaction. For the proof workflow, generate the expected journal in a separate invocation from the independent claim and compiled guest ID, rather than taking expectations from the proof.
