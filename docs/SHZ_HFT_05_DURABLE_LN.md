# SHZ-HFT-05: crash-safe reference router and authenticated commitment acknowledgements

Stacked on HFT-04 (#29). This reference closes the local journal/replay and signed acknowledgement state-machine gates; actual LDK/Lightning settlement, atomic cross-channel updates, signer provisioning, storage anti-rollback and operational deployment remain external gates.

## Accounting

For every immutable router allocation: cap = free + resting + pending + committed + paid_fees. Committed is encumbered DLC collateral, not reusable trading credit. Paid fees are a cumulative debit against the original cap; no refill, DLC closure or withdrawal is implemented. Existing exact per-fill margin and incremental fees are retained. Only matching-generated batches enter the journal. Sealing leaves pending intact.

Phases: SEALED -> PREPARED (all channel-owner batch approvals authenticated and synced) -> COMMITTED or FENCED_ABORT (one complete, ordered, signed bundle for the next unresolved sequence). Prepare must complete durably before submitting to the external channel adapter. COMMITTED atomically moves pending margin into committed and pending fee into paid_fees, recognizing the exact oracle/router split in the reference ledger. FENCED_ABORT requires authenticated proof-attestation of irreversible no-effect cancellation across every participating lane, with unchanged physical commitment head, and returns only the pending margin+fee to free. Cancel residual resting quotes of aborted maker intents; never restore filled quantity or reuse the taker intent. Already produced later fills remain reserved and retain their originally authorized fee amounts; tiny cumulative rounding differences after an abort are not recomputed. No timeout, disconnect, unilateral router assertion, incomplete/forged bundle, or unprepared event releases matched reservations.

## Acknowledgement wire contract

Every lane belongs to a specific router allocation and has pinned owner, distinct peer and distinct monitor keys plus a starting commitment head. Each channel acknowledgement signs a domain-separated digest of the canonical genesis config (network, epoch, policy, engine, complete signed allocation registry, lane identities, recipient keys), exact batch digest/sequence, disposition, channel outpoint, owner, exact per-channel margin and fee, previous and next heads, external evidence digest, fee receipt digest, and batch recipient totals. Verify owner, peer and monitor BIP340 independently. Commitment increments both logical revision and adapter commitment counter by one and changes the state hash; abort increments only logical revision and leaves adapter commitment counter/hash unchanged. Fee-paying commit requires a nonzero unique fee receipt digest; nullifiers are replayed from WAL. Fee-free commit and abort require zero fee receipt. All accounts appear exactly once in canonical order. Validate the whole bundle before mutation; exact retry is idempotent, conflicting replay rejected. Resolving batches strictly in order prevents skipping a prepared or unresolved batch.

The monitor is a trusted reference attester here: the nonzero evidence digest represents an externally verified transcript; code does not parse BOLT commitment_signed/revoke_and_ack, verify actual remote monitor persistence, validate CET funding, verify payment preimages, check real peer state or prove atomicity across multiple channels. The mock receipt and reference paid ledger are not actual realized revenue. The production adapter must derive and validate real previous/new commitment transaction and monitor persistence, exact DLC spendability, fee debit and recipient credit evidence, enforce irreversible abort fencing, reconcile after peer disconnects, and attest only after full durable commitment. If one participant commits while another is uncertain, hold *all* matched reservations, do not issue FENCED_ABORT. Logical router allocation lanes do not independently advance the same physical LN funding channel: externally serialize and fence shared channel commitments. The reference starts with externally reconciled unencumbered caps; it cannot infer balances from Bitcoin. Use distinct channel security keys, independent monitors, and actual channel-specific state authority before deployment.

## Journal

Reference append-only binary frames: 8 byte SHZWAL05 magic, genesis config hash frame, then length-u32 LE, JSON event bytes, SHA256 tagged frame digest over prior digest, monotone record number, length, bytes. Frame cap 16 MiB. One File::try_lock writer per journal (Unix host; advisory, not distributed fencing), create_new and sync directory on create; never replace or unlink active inode. Each command is appended and sync_all completed before applying it and returning result. Rejected calls are recorded too, because router clock can advance on rejection. Replay from authenticated initial registry and same semantic version/engine reproduces queue, book, mark, clock, sequence, exact fills, seal cursor, approvals, acknowledgements and balance accounting. Partial/torn/corrupt frames or config mismatch fail closed; a failed sync poisons the writer. No silent truncation or automatic repair. A caller can pass an independently persisted minimum tip, detecting rollback even to a valid earlier prefix. The pin must be protected outside the journal and advanced according to external acknowledgement policy; hash chain alone does not authenticate against malicious rewriting or valid-prefix rollback. No external side effect is issued before durable PREPARED; post-crash reconcile from the prepared batch and re-fetch the identical ack from the adapter, then persist and apply idempotently. Fully persisted Resolve replays if crash occurs between fsync and memory mutation/reply. Restarts must restore the same trusted clock timeline or establish a fenced new epoch, never reset order/expiry clocks.

Reference fsync per command is deliberately conservative and will dominate HFT latency. Production needs bounded group commit or a replicated transactional WAL with durable acknowledgements only after flush, process/host fencing, disk-full handling, encryption/access control, checkpoints, compaction and a load test; no benchmark extrapolation from HFT-02. Memory retains historical receipts and batches, not a production bounded archive. Journal corruption or external head mismatch requires independent reconciliation, no balance release.

## Test gates

Native tests exercise replay of queue and rejected clock advance, exclusive writer lock, batch/approval recovery, unprepared/partial/forged/stale acks, missing/reused fee receipt, exact fsync-before-apply crash cut, duplicate and conflicting acknowledgement, committed margin never free, authenticated abort with unchanged physical head and cancelled residual quotes, exact fee conservation, valid-prefix rollback, corruption/torn tail and config substitution.
