The saved report has no hash or proof cases because the sandbox request failed with "Failed to buffer the request body: length limit exceeded". This is a transport-stage failure, distinct from the original ADMIT-08 execution-gas failure.

This repair strips symbols, records build size/hash/optimization level, falls back to size optimization if the stripped optimized artifact remains above 1,500,000 bytes, and sets the ephemeral sandbox JSON-RPC payload limit explicitly to 16 MiB using near-sandbox 0.3.5's additionalConfig. The effective config is read back from sandbox.dump(). The only sandbox override is rpc.limits_config.json_payload_max_size. Normal protocol deployment limits and the 300 TGas function-call budget are unchanged. The script records deployment, initialization, hash benchmark, and proof replay stages. Successful hash arms must return identical words, and the application gate now requires an accepted actual receipt and explicit false responses for all three corrupt-input cases, rather than treating transport failures as cryptographic rejection.
