# CBM-CACHE-02: clearing candidate verification replay

## Scope
Synthetic candidate workloads only. The Python fixture uses a restricted independent BIP341 message encoder (no annex, script-path key version zero, no code separator), deterministic BIP340 signatures with public test-only keys and actual OpenSSL EC_POINT_mul verification. The fictitious outpoints and P2TR-shaped scripts are not live funded vaults or claims of executable script paths. The native Rust integration test uses the repository's actual Mnr02TaprootTree, derive_utxoref_funding_output, SegwitTx::bip341_sighash and BIP340 verification, with fictitious outpoints and direct test signatures (not adaptor completion). Neither test runs the production packer/signing or settlement path. Existing packer call sites explicitly verify a subset of the intended complete signature set; the fixture includes all sixteen checks, so the measured work is not the current packer's measured hot path. Native test timing and regtest remain pending. Local Rust toolchain unavailable.

## Local executed experiment
Nine traces: regimes stable pinned, rotating, high churn; three deterministic roots 91,92,93 each. Each uses 24 distinct generated drafts, each with four offline and two bilateral inputs, six payout outputs plus anchor, and exact satoshi conservation including a 1500-sat fee. Each presentation requests four pinned 0x83, eight ALL, four DEFAULT verification tuples. Every third draft is immediately retried and one earlier draft is revisited, giving 40 presentations per trace. The exact 128-byte key is public key || recomputed digest || signature. Positive-only admission after successful cold checks; all timed online policies perform real crypto on misses. Cache capacity fixed in entries; Python allocation overhead and policy metadata not equalized or measured. LFU counts only resident accesses, evicts oldest minimum count; pinned priority preferentially evicts nonpinned entries, bypassing nonpinned requests when all slots pinned. Offline optional-admission interval oracle minimizes unit misses with perfect future access information; no runtime benefit inferred from oracle. All policies use the same immutable valid requests. Eleven committed-field/hash-type mutation checks, three uncommitted-field checks, one paired input/output reorder and four exact tuple mutation checks pass. Uncommitted mutations preserve pinned verification but invalidate the original full signature. This does not authorize those transactions.

## Native gate and integration blockers
Run `cargo test --release --locked -p shz-utxoref --test cbm_cache_replay -- --nocapture`. The targeted workflow reports actual native timings and checks both cached and cold verification, including digest mutations. Native fixture order differs from Python; do not expect identical miss counts. No live cache integration yet. On PR35's initial commit, workspace tests including the two original cache unit tests passed (run 45955865988), strict clippy failed in existing shz-frost-member code and downstream regtest stages were skipped. This does not establish a green workspace.

Source review of pnl_batch.rs at blob d42c4fb2112664e824c55e5cc2995c4a5f7a0899: (1) reserve_before_signing checks self.consumed_obligation_ids, while solve_and_verify_pnl_batch checks outpoints against snapshot.spent_outpoints; explicitly enforce authoritative self.spent_outpoints and the required snapshot replay-set relationship at reservation, independent of caller data. (2) confirm_active_chain checks signed txid and copies replay IDs/outpoints from caller-supplied settled_snapshot; explicitly check its snapshot_hash against verified_batch.snapshot_hash before mutating replay sets, or derive replay sets from the durable reservation itself. Audit callers and trusted active-chain evidence as well. These are source-level concerns, not tested exploits; callers may impose additional gates. Add reject-without-mutation regression cases and restart/reorg/concurrency tests before wiring a cache into live signing. No production state-machine changes in this PR.

Capital-time is the integral of actually locked sats over time. Even an observed pure verifier speedup moves the capital bound only if verification is on the binding critical path to lawful collateral reuse. Maturity, confirmations, liquidity and dispute requirements cannot be bypassed. No sat-second savings measured.
